| Node.js | 声明 22+，建议使用验证环境 Node.js 24 |

这些是已测试范围，不是所有更高版本都兼容的承诺。原生 CLI 接口和 DSH 提供方 API 改变时需要重新验证。

## 本机配置

编排数据默认位于当前用户 DSH 数据目录下的 `orchestrator`，支持 `DSH_HOME` 和插件 `dataDir`。Claude 配置读取 `CLAUDE_CONFIG_DIR`，Codex 读取 `CODEX_HOME`，均有当前用户主目录默认值。正式插件不绑定维护者的用户名、账号、项目路径、网关端口或模型 ID。

CLI 登录和模型可用性由使用者的账号决定。模型目录是候选清单，不保证账号权限；别名可能映射到同一个实际模型。

## 常驻终端

执行、审核使用独立任务阶段会话，最多 4 个活跃 PTY，默认调度并发 2；自动空闲终端 30 分钟回收，人工终端不被自动挤掉。关闭弹窗不等于关闭 CLI 或交还控制权。

原生通知关联调用标记；Claude 另确认 session idle，Codex 过滤隐藏标题通知。启动等待、清理失败、完成事件无法证明时会停止流转。首轮 Codex 中断时可能尚无可靠 session ID。宿主重启或用户暂停后不会自动重放任务。

Claude 的 PermissionRequest 通过当前协调会话的 DSH 原生选项界面显示完整工具参数。等待时暂停该调用的执行超时；选择“允许本次”或“拒绝”后，只向对应的原生请求返回决定，随后继续当前调用。不会更新长期权限。若界面不可用、选择无效或等待过久，则保留 Claude 的原生授权提示并暂停编排，可接管终端处理。请求参数会临时保存在本用户专属的权限文件中，处理完成后删除；其他输出记录不保存参数。

第三方 Claude 网关使用 CLI 的预先加载工具开关，避开部分网关不接受的动态工具消息；可能占用更多上下文。CLI 自动压缩仍然生效，手动压缩需要接管。兼容设置仅用于子 CLI，不修改用户全局配置。
